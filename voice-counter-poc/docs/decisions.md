# 設計判断の記録（ADR）

各判断に「誰が決めたか」を付けています。

- **依頼者**: 依頼者の回答に基づく判断
- **Claude（自走）**: 回答がなかった、または曖昧だったため Claude が決めたもの。**見直しの候補**です

---

## ADR-001 STT に Gemini 3.5 Transcribe Live を使う
- **決めた人**: 依頼者の希望を Claude が解釈
- **背景**: 「Google の AI の STT。新しいものが出たと思うので最新のものを使いたい」という回答。
- **判断**: 2026-09 時点で Gemini API のドキュメントに載っている STT 専用のリアルタイムモデル `gemini-3.5-transcribe-live`（Live API）を使う。
  - 候補だった Cloud Speech-to-Text の Chirp 3 は、GCP プロジェクトとサービスアカウントの設定が必要で、ブラウザから直接つなぐ手段（ephemeral token）も無いので見送った。
- **影響**: `languageCodes: ["ja-JP"]`、ナレッジのキーワードを `customVocabulary` に渡す、セッションは最長 10 分（自動で再接続する）。
- **出典**: https://ai.google.dev/gemini-api/docs/live-api/live-transcribe

## ADR-002 TTS に Gemini 3.8 Flash-Lite TTS を使う
- **決めた人**: 依頼者の回答を Claude が解釈（「音声の受け取り…Google の AI を使う」）
- **判断**: ドキュメントで「会話型の音声エージェント向け」とされている `gemini-3.8-flash-lite-tts` を使う。stream で PCM を受け取る。声は `Kore`、話し方は `TTS_STYLE` で指定する。
- **見直しの観点**: 日本語の自然さは未評価。`TTS_VOICE` や `TTS_STYLE` を変えるか、上位の `gemini-3.8-flash-tts` と比較する。

## ADR-003 LLM を GPT-4o-mini から Gemini 3.5 Flash-Lite に変更する
- **決めた人**: **Claude（自走）**
- **理由**: STT と TTS が Gemini になったので、LLM もそろえれば API キーが 1 つで済み、セットアップが簡単になる。軽量モデル + `thinking_level: minimal` で、最初のトークンまでの時間を短くすることを狙った。
- **戻し方**: `llm.ts` の `Generator` 型を満たす OpenAI 版の実装を追加し、`session.ts` の `buildDeps` を切り替える。

## ADR-004 STT はブラウザから Google に直接接続する
- **決めた人**: **Claude（自走）**。依頼者の「ブラウザでの処理でも問題ない」を前提にした
- **理由**: 音声を Worker 経由で中継すると、往復の遅延と Worker の CPU 時間が増える。Live API は ephemeral token でブラウザから直接つなげる。
- **トレードオフ**: 将来、電話（サーバー側 STT）に対応するときは、DO から Live API につなぐ実装が別途必要になる。`SttEngine` インターフェースを境界にしているので、クライアント側への影響は小さい。

## ADR-005 判定直後に復唱し、LLM を待たずに声を出す
- **決めた人**: Claude が提案し、依頼者の要件（「復唱を含めて違和感のないテンポ」）に合致
- **判断**: ナレッジのフロントマターの `ack` を、Jev の判定直後に読み上げる。同じ文言の音声はキャッシュする。LLM には「復唱は済んでいる」と指示して、二重にならないようにする。

## ADR-006 Jev は choice 質問 1 つで全トピックを判定する（2 段階にはしない）
- **決めた人**: **Claude（自走）**
- **理由**: PoC のトピックは 12 件で、choice の上限 255 件に十分収まる。1 回の呼び出しで済むので遅延も最小になる。
- **スケールの方針**: 市役所サイト全体の規模になったら、次のどちらかに拡張する。
  1. カテゴリ判定 → カテゴリ内のトピック判定の 2 段階（Jev を 2 回呼ぶ）
  2. Jev でカテゴリを判定し、その中を全文検索やベクトル検索で絞り込む
- **出典**: https://docs.typesafe.ai/api

## ADR-007 半二重にする（割り込みには対応しない）
- **決めた人**: 依頼者（「まずは対応不要」）
- **判断**: AI の応答中は STT を止める。エコー対策も兼ねる。

## ADR-008 確信度のしきい値 0.6 で聞き返す
- **決めた人**: **Claude（自走）**
- **判断**: `ROUTE_CONFIDENCE_THRESHOLD=0.6`。これを下回ったら、確率の上位 2 候補から聞き返す。
- **見直しの観点**: Jev の confidence の分布を実データで見て調整する。評価データセットで決めるのが望ましい。

## ADR-009 範囲外の質問には定型文で答える
- **決めた人**: 依頼者（「確認のうえ再度連絡する旨、またはウェブサイトへの誘導」）
- **判断**: `OUT_OF_SCOPE_MESSAGE` に両方を含める。LLM は呼ばない（速く、誤回答もしない）。

## ADR-010 API キーが無くてもモックで一通り動くようにする
- **決めた人**: **Claude（自走）**
- **理由**: キーが無い開発環境でもパイプライン・UI・計測を確認でき、CI でも使える。モックの種類は画面の上部に表示する。
- **注意**: モック分類器はキーワード一致なので、判定精度の評価には使えない。

## ADR-011 Hybrid VAD は実験扱いで、既定は OFF にする
- **決めた人**: **Claude（自走）**
- **理由**: `audioStreamEnd` を送った後も同じセッションで認識を続けられるかは、ドキュメントの記述からは確証が持てない。実機で確認するまでは、安全側の設定（サーバー側の自動 VAD）を既定にした。

## ADR-012 フロントは Vite + React の SPA にし、本番は Worker の Static Assets で配信する
- **決めた人**: 依頼者（「Vite + React、シンプルに」）+ Claude（配信方法）
- **判断**: 開発時は Vite（:5173）から wrangler dev（:8787）へプロキシする。本番は `web/dist` を Worker の assets で配信し、同じオリジンにする（CORS が不要になる）。

## ADR-013 会話状態は DO Storage に置く
- **決めた人**: **Claude（自走）**
- **理由**: Hibernation でメモリが消える。`serializeAttachment` は 2KB 上限なので、日本語の会話履歴には小さすぎる。
